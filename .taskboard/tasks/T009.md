## 背景

主会话"跟进进度"时，`atb status` 只能看到提交数（AHEAD/BEHIND）和改动文件数，看不出：
- worktree 里有多少**还没提交**的改动（Agent 正在干活，但还没 commit）；
- 每个任务**多久没动静**了（是卡住了，还是刚开工）。

主会话只好手写 shell 脚本：每 45 秒比对一次各任务分支的提交和任务单状态，一有变化就退出、提醒自己去审查。这正该是 atb 自己的功能。

## 要做的事

1. **`atb status` 新增两列**
   - `DIRTY`：worktree 里未提交的文件数（`git status --porcelain` 的条目数；worktree 不存在时显示 `—`）。
   - `IDLE`：距离最近一次活动多久，活动时间取"分支最新提交时间"和"worktree 里未提交文件的最新修改时间"两者中较晚的那个；显示成 `3m`、`2h`、`1d` 这样的格式。只看文件的 mtime，不读文件内容。
   - `--json` 输出同步新增 `dirty` 和 `idle_seconds` 两个字段（保留原有字段不变）。
2. **新命令 `atb watch`**
   - 阻塞等待，直到任意任务出现下列变化之一，然后打印变化摘要并退出（退出码 0）：任务状态变了、分支有新提交、新增了任务单。
   - 参数：`--interval SECONDS`（默认 30）、`--timeout SECONDS`（默认不限；超时后打印"无变化"，退出码 3）、`--json`。
   - 摘要每行一个变化，例如 `T007 doing → review`、`T008 新提交 2 个（a1b2c3d）`。
   - 只读 git ref 和任务单，不 fetch、不改任何文件。
   - 设计成既能给人在终端里用，也能给主会话放在后台用：退出即代表"该去看看了"。
3. **修 `atb dispatch` 的一处问题（审查 T007 时发现）**：`todo` 状态的任务，转发句现在只写 `prompt T009`，但 Agent 必须先运行 `start` 才有 worktree。改成：`todo` 任务的转发句写"先运行 `… start <ID>`，再运行 `… prompt <ID>`"；`doing` 只写 `prompt`；`rework` 保持现在的"被打回了"说法。加测试。
4. **README 中英文**补上新的两列和 `watch` 的用法。CHANGELOG 新建 0.1.2 条目（中英双语）。版本号由主会话合并时改。
