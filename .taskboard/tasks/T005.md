## 要做的事

1. **`atb done ID [--merge] [--clean] [--force]`**
   - 只接受 `review` 状态（`--force` 可以放宽到 `doing`，并输出警告）。
   - 先跑一遍和 `check` 相同的检查：有越界、或有未提交改动、或最近一次测试记录不是通过（没有记录也算），就以退出码 1 拒绝。`--force` 不能跳过越界检查。
   - 不加 `--merge`：只把状态改成 `done`，提示用户自行合并。
   - `--merge`：要求当前目录是主仓库、当前分支正是 `config.target`、且合并不会碰到工作区里有改动的文件；然后执行 `git merge --no-ff <branch> -m <消息>`。消息模板来自 config 新键 `merge_message`，默认 `"Merge {branch} ({id}: {title})"`，加进 `config.py` 的默认值和类型表。合并有冲突时执行 `git merge --abort`，退出码 1，状态不变。
   - `--clean`（只能和 `--merge` 一起用）：合并成功后 `git worktree remove`（worktree 有改动就拒绝，不加 `--force`），再 `git branch -d`（**绝不用 `-D`**）。
   - 成功后写回 `status = "done"`，不自动提交任务单，输出提示。**永远不 push。**
2. **`atb board --html FILE`**：单文件静态看板。
   - 内容和 `status` 一致（每个任务一行，外加汇总），再加上 `conflicts` 的三类结果。
   - 暗色优先，跟随 `prefers-color-scheme` 切换到浅色；内联 CSS，**不引用任何外部资源**（没有 `http://`、`https://`、CDN、字体）。
   - 所有任务字段都用 `html.escape` 转义（标题里可能出现 `<script>`）。
   - 状态用徽章区分，越界数大于 0 时高亮；`missing` 也要能正常显示。
3. **`atb review ID --lang zh|en`**：审查表现在固定输出中文。加上 `--lang`，默认 `zh`；英文版的标题、小节名、检查项都用英文。模板放到 `prompts.py` 或新模块，不要在 cli 里写死字符串。
4. **README**：两份 README 命令表里 `done`、`board --html` 的状态从 Planned 改为已实现，并补上 `review --lang`。只改这几处。
