## 背景

协作时最常见的问题是"这个任务卡在哪了"：窗口中断、等确认、方向不确定，这些信息现在只能靠人工转述，atb 里看不到。T034 给每个任务加一条轻量的备注流：agent 或人都能随手记一句，`atb log` 的时间线里能看到。

## 要做的事

1. **新命令 `atb note ID [TEXT] [--by NAME] [--json]`**
   - 带 TEXT：追加一条备注。TEXT 支持 `@FILE` 形式，读取文件内容，和 `atb new --body @FILE` 的约定一致。
   - 不带 TEXT：按时间顺序列出这个任务的全部备注；加 `--json` 输出结构化结果。
   - `--by` 默认取任务单里的 `agent`。
   - 存储：`.taskboard/notes/ID.jsonl`，每行一条，包含 `timestamp`（UTC ISO 8601）、`by`、`text`。和 `.taskboard/runs/` 一样不进 git：`atb init` 写的 `.gitignore` 要加上这一行，已初始化的仓库由 `atb doctor` 提示补上。
   - 校验：
     - 空文本，或只有空白的文本，报错退出。
     - 单条超过 4000 个字符，报错退出，不要截断后写入。
     - 任务不存在，报错退出。
     - 已完成（done）的任务仍然允许追加备注。
2. **时间线：** `atb log ID` 把备注按时间插进时间线，类型为 `note`，和状态变化、测试、合并事件排在一起。`--json` 里同样出现。
3. **评审：** `atb review ID` 的文本输出和 `--json` 都显示最近 3 条备注。
4. **中英双语：** 用户可见的文字跟随现有的 `--lang` 机制。
5. **文档：** `README.md` 和 `README.zh-CN.md` 的命令列表各加一行。CHANGELOG 不用改，由主会话来写。

## 测试

- 追加、列出、`--json`、`@FILE`
- 空文本、超长文本、任务不存在
- 时间线顺序：备注夹在两次状态变化之间
- `review` 只显示最近 3 条
- `.gitignore` 包含 notes 目录
