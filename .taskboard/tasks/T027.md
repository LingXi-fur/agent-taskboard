## 背景

协调者要决定"下一单给哪个 agent"，但现在看不出各 agent 的历史表现。`.taskboard/` 的历史记录（`atb log` 用的那份）已经有状态变化和时间戳。

## 要做的事

1. 新命令 `atb stats [--since YYYY-MM-DD] [--agent NAME] [--json] [--lang zh|en]`，按 agent 汇总：
   - 完成数（done）、放弃数（dropped）、进行中数
   - 返工率：至少返工一次的任务占比，以及平均返工次数
   - 周期：从 `start` 到 `done` 的中位数和 P90；从最后一次进入 `review` 到 `done` 的中位数，也就是等待审查的时间
   - 最近一次测试失败率：done 任务里，最后一次 `check --test` 失败过的比例
2. 只读：不改任何文件，不调用会产生锁的 git 命令（走 `gitops.git_env()`）。
3. 历史数据缺失或不完整时（早期任务没有记录），对应项显示"—"，并在底部说明有几个任务缺少历史。不要让命令报错。
4. 性能：200 个任务时耗时小于 0.5 秒。用 `scripts/bench_status.py` 的造数方式，或者另写一个 bench 脚本测量。
