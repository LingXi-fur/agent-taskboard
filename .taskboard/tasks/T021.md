## 背景

协调者合并完任务后要记得 push，之前忘了推，积压过 55 个提交。atb 目前只合并、从不 push（"never pushed"）。默认不 push 的原则保留，但应该提供一个显式开关，并且让"有多少没推"一眼可见。

## 要做的事

1. `atb done ID --merge --push`：合并成功后，把目标分支 push 到它的上游（`git push <remote> <target>`；没有上游时用 `origin`，origin 也不存在时报清晰的错误并以非零码退出，合并本身保留）。
   - 绝不 force push。
   - push 被拒绝（non-fast-forward）时，提示先 `git pull --rebase` 或手动处理，不自动重试。
   - 不加 `--push` 时行为与现在完全相同。
2. 配置项 `push_after_done = false`（`.taskboard/config.toml`，默认 false）。设为 true 时 `done --merge` 默认 push；`--no-push` 可临时关闭。
3. `atb status` / `board`（文本和 `--json`）在顶部显示目标分支相对上游领先/落后的提交数，例如 `main: 3 commits not pushed`；没有上游时显示 `no upstream`。只读本地已有的 remote-tracking 分支，**不要自动 fetch**（保持离线、快速）。
4. `atb doctor`：目标分支领先上游超过 0 时给 WARN（提示 push），没有上游时给 INFO/WARN 说明，不算 FAIL。
5. 测试 `tests/test_push.py`：在临时目录建一个 bare 仓库当 remote，覆盖 push 成功、无上游、被拒绝、配置默认 push、`--no-push`、status/doctor 的显示。不能访问网络。
