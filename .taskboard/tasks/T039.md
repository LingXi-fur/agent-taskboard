## 背景

tokens 项目（另一个仓库）想回答"每合并一个任务平均花多少钱、哪个 agent 返工最多"。tokens 知道每个会话花了多少钱，atb 知道每个任务对应哪些会话、返工了几次、有没有合并。所以需要 atb 提供一个**稳定、有版本号的只读导出接口**，让其他工具读取。tokens 会用子进程调用它。

## 要做的事

1. **新命令 `atb export --json [--since YYYY-MM-DD]`**，输出一个 JSON 对象：

   ```json
   {
     "schema": 1,
     "generated": "<UTC ISO 8601>",
     "repo": "<主仓库绝对路径>",
     "target": "main",
     "tasks": [
       {
         "id": "T036", "title": "…", "agent": "opencode", "status": "done",
         "branch": "…", "created": "<UTC ISO>", "done_at": "<UTC ISO 或 null>",
         "merged": true, "merge_commit": "<sha 或 null>",
         "rework_count": 1,
         "sessions": [
           {"adapter": "claude-code", "id": "<工具原生会话 ID>",
            "started_at": "<UTC ISO>", "last_active_at": "<UTC ISO>"}
         ],
         "usage": {"input": 0, "output": 0, "cache_read": 0, "cache_write": 0, "total": 0}
       }
     ]
   }
   ```

   - **`sessions`：** 复用 T036 的 `sessions.py` 会话→任务对应关系，不要另写一套。会话 ID 必须是各工具的**原生 ID**（Claude Code 的 sessionId、Codex 的 rollout id、OpenCode 的 session id、Gemini 的 sessionId），这样其他工具才能对上。
   - **扫描窗口：** 导出时默认扫描全部历史会话，不受 T036 的 7 天窗口限制。`--since` 只看最后活动在这之后的任务。如果全量扫描太慢，就加一个缓存，或者加上 `--max-days` 参数。不管怎样，都要在回报里写出真实数据上的耗时。
   - **`usage`：** 没有数据时为 `null`，不要填 0。
   - **`--json`** 是唯一的输出格式。不带 `--json` 时打印一句用法说明，退出码为 2。
2. **文档：** 新建 `docs/export.md`（中英文各一份）写明字段含义和稳定性承诺：同一个 schema 版本内只新增字段，不删字段、不改字段含义；要做破坏性修改就把 schema 加 1。README 两份的命令列表各加一行。
3. **测试：**
   - 字段完整性：每个字段都在，类型正确。
   - 原生会话 ID 和 fixture 一致。
   - `--since` 过滤正确。
   - 在任务 worktree 里运行时，`repo` 指向主仓库。
   - 输出能用 `json.loads` 解析，没有多余的打印混进 stdout。
