## 背景

主会话协调时常遇到的"环境问题"都要靠人工排查：任务单写坏了解析不了、worktree 被手动删了但任务还是 `doing`、`done` 任务的残留没清、git 版本太旧导致 `merge-tree` 冲突检测失效。需要一个一次性体检命令。

## 要做的事

新命令 `atb doctor [--json]`，逐项检查并输出 `OK` / `WARN` / `FAIL`，每项一行，附一句说明和建议命令：

1. **git 版本**：`git merge-tree --write-tree`（冲突检测依赖它）需要 git ≥ 2.38；低于则 FAIL。
2. **配置**：`.taskboard/config.toml` 能加载；`target` 分支存在；`worktree_root` 的父目录可写。
3. **任务单**：每张都能解析（失败 → FAIL，列出文件名）；文件名和 `id` 一致；`depends` 指向存在的任务。
4. **活跃任务**（`doing`/`review`/`rework`）：分支和 worktree 都在（缺失 → FAIL，建议怎么处理）；worktree 当前分支和任务单一致。
5. **收尾残留**：`done`/`dropped` 任务还有 worktree 或分支 → WARN，建议 `atb gc`。（复用 `gc.py` 的判断，不要重写。）
6. **孤儿 worktree**：`worktree_root` 下有 git 认识、但没有任何任务单对应的 worktree → WARN。
7. 退出码：有 FAIL 为 1，否则 0。只读，不改任何文件、不 fetch。
