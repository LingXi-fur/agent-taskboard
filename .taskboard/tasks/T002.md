## 第一部分：T001 审查遗留的修复（必须先做）

主会话做边界探测时发现了 3 个问题。因为本任务的 `start` 会把任务单写回磁盘，这些问题必须先修：

1. **CRLF 换行**：用 `\r\n` 保存的任务单会报 "unterminated '+++' header"。解析时按 `splitlines()` 识别头部边界（`+++\r` 也算结束行）；`dump` 一律输出 `\n`，并在 docstring 里写明这一点。
2. **BOM**：以 `﻿` 开头的文件会报 "must begin with '+++'"。解析前去掉开头的 BOM。
3. **未知字段写回会损坏文件**：
   - `"needs quote" = 1` 这类键，`dump` 原样写出 `needs quote = 1`，重新解析就失败。键名符合 `[A-Za-z0-9_-]+` 的按裸键输出，否则用 `_format_string` 加引号。
   - 值是 dict（比如 `[meta]` 表或内联表）时，`dump` 会抛 "unsupported value type"。改为输出 TOML 内联表 `{ k = v, ... }`，支持递归。
   - 测试：上面每种情况都要验证 `parse(dump(parse(x))) == parse(x)`。

## 第二部分：开工、交接、检查

1. **`gitops.py`**：对 git 的薄封装，所有调用都用 `subprocess.run([...], check=False)`，失败时抛出带 stderr 的 `GitError`。
   - `rev_parse(rev)`、`branch_exists(name)`、`worktree_add(path, branch, base)`、`worktree_list()`（解析 `--porcelain` 输出）、`rev_list_count(a, b)`（返回领先和落后的提交数）、`merge_base(a, b)`。
   - `changed_files(base, head)`：用 `git diff --name-status -z -M base...head`。改名要同时返回新旧两个路径。
   - `uncommitted_files(worktree)`：用 `git status --porcelain=v1 -z --untracked-files=all`，包含未跟踪文件，正确处理 `-z` 下改名条目的两段格式。
2. **`atb start ID [--base REV] [--force]`**
   - 只接受 `todo` 或 `rework` 状态。`depends` 里的任务没有全部 `done` 时，以退出码 1 拒绝开工，`--force` 可以跳过，但要输出警告。
   - 基线默认取 `config.target` 的当前提交，在任务单里写入完整 SHA。worktree 路径是 `worktree_root/<ID>`；分支名优先用任务单里的 `branch`，为空时按 `branch_pattern` 生成。
   - `todo` 时：分支或路径已经存在就报错（退出码 2）。`rework` 时：复用已有的 worktree 和分支，不新建。
   - 把 `base`、`branch`、`status = "doing"` 写回任务单，正文保持原样。**不自动提交**，在输出里提示用户自行提交任务单。
3. **`atb prompt ID [--lang zh|en]`**：输出给 Agent 的完整交接文本，模板放在 `prompts.py`，内容包括：
   - worktree 绝对路径和 `cd` 命令，分支名；
   - 允许修改和禁止修改的通配符列表；
   - 规则：不 push、不合并、不改范围外的文件、提交前运行测试命令（任务单的 `test`，为空时用 config 的）；
   - 回报格式：改了哪些文件、测试数字、分支名、遇到的问题；
   - 任务单正文原文；如果正文里有 `## 返工` 小节，要放在最前面并加醒目标记。
   - `--json` 输出 `{"text": ..., "worktree": ..., "branch": ...}`。
4. **`atb check ID [--test] [--strict] [--json]`**
   - 改动集合 = 已提交的 `changed_files(base, branch)` + worktree 里未提交的改动，改名同时检查新旧两个路径。用 `scope.classify` 分类。
   - 输出：领先和落后的提交数、改动文件数、越界列表（`denied` 和 `outside` 分开列）、未提交文件列表。
   - 有越界时退出码为 1。有未提交改动时默认只警告；加 `--strict` 时也返回 1。
   - `--test`：在 worktree 里运行测试命令。用 `shlex.split` 拆分参数，不经过 shell；超时取 config 的 `test_timeout`（默认 1800 秒，在 config 里加这个默认值）。结果追加写入 `.taskboard/runs/<ID>.jsonl`，包括时间戳、退出码、耗时、命令，以及输出的最后 4KB。测试失败时退出码为 1。
