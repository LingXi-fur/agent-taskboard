## 要做的事

1. **`atb status [--json]`：看板**
   - 每个任务一行：ID、状态、Agent、标题（按显示宽度截断）、分支、领先和落后提交数（相对 `config.target`）、改动文件数、越界数（denied + outside）、最近一次测试结果（取 `runs/<ID>.jsonl` 最后一行，显示 ✓、✗ 或 —）。
   - 只有 `doing`、`review`、`rework` 状态的任务才计算 git 指标；`todo`、`done`、`dropped` 显示 `—`，避免对已删除的分支报错。
   - 分支或 worktree 已经不存在时，显示 `missing`，不要抛异常。
   - 末尾一行汇总：各状态的任务数。
2. **`atb conflicts [--json]`：跨任务冲突**
   - 对所有活跃任务（doing/review/rework），两两求改动文件的交集（复用 T002 的 `changed_files`，加上未提交的改动）。
   - 对有交集的任务对，用 `git merge-tree --write-tree --name-only A B` 确认是否真的冲突。这个命令不碰任何 worktree。退出码 1 表示有冲突，冲突文件列在输出里。
   - 每个活跃任务再和 `config.target` 的最新提交比一次：基线之后 target 上新改动的文件，和任务改动的文件有没有交集（也就是基线漂移）。
   - 输出分三类："真实冲突"、"同文件但能自动合并"、"基线漂移"。存在真实冲突时退出码为 1。
3. **`atb review ID [--out FILE]`：审查表**
   - 生成 Markdown，包含：任务头部摘要、check 结果（越界和未提交改动）、最近一次测试结果、diffstat（`git diff --stat base...branch`）、与其他活跃任务的冲突情况，以及从正文 `## 验收` 小节原样复制过来的复选框清单，加一个空的"审查意见"小节。
   - 默认输出到 stdout；`--out` 时写入文件。
   - 运行后把任务状态从 `doing` 改为 `review`；状态已经是 `review` 时保持不变。
4. **`atb rework ID --note TEXT`：打回**
   - 状态改为 `rework`。在正文末尾的 `## 返工` 小节追加一条带时间戳的条目（小节不存在就先创建），多次打回按时间顺序累积。
   - T002 的 `prompt` 已经支持把返工小节排在最前面，写一个端到端测试证明两者能配合：rework 之后 prompt 的第一个正文小节就是返工意见。
   - `--note` 也接受 `@file` 形式，从文件读取多行审查意见。
