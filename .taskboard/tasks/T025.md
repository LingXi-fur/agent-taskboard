## 背景

协调者每写一张任务单，要先运行 `atb new` 生成只有元数据的空单，再手动用脚本把正文接到第二个 `+++` 后面。返工说明虽然有 `atb rework --note @file`，但改 allow/deny 时也得手改 TOML。这些手工步骤容易出错。另外，协调者的编辑器只能打开某个目录里的文件，所以还要把任务单复制一份过去。

## 要做的事

1. **`atb new TITLE ... --body @FILE`**（`--body -` 表示从 stdin 读取）：创建任务单时直接写入正文。不传 `--body` 时行为和现在一样。
2. **`atb edit ID`**，可组合的选项：
   - `--body @FILE|-`：替换正文，元数据保持不变。
   - `--add-allow GLOB` / `--remove-allow GLOB` / `--add-deny GLOB` / `--remove-deny GLOB`：可以重复使用。
   - `--title TEXT`、`--agent NAME`。
   - 修改后的任务单要能通过现有的解析校验；校验失败时不写入，报错并以非零码退出。
   - 不允许修改 `id`、`status`、`branch`、`base`（状态由各子命令维护）。`done`/`dropped` 状态的任务不能编辑。
3. **`atb new`/`atb edit` 加 `--copy-to DIR`**：写入后再把任务单复制一份到 `DIR/ATB_TASK_<ID>.md`。目录不存在时报错，不要自动创建。
4. 正文前后的空行要规范化：写入后，第二个 `+++` 后面只留一个空行，文件以单个换行结尾。
5. 所有 git 调用都走 `gitops.git_env()`；文件读写一律用 UTF-8（Windows CI 已经开了，见 T022）。
