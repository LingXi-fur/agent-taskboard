## 背景

`atb done --merge --clean` 只在合并的那一刻清理。没加 `--clean` 合并的任务、手动合并的任务、改成 `dropped` 的任务，worktree 和分支会一直留着。本仓库现在就有：T001–T004 早已 `done`，但 `../agent-taskboard-tasks/T001`…`T004` 四个 worktree 和对应分支都还在，`git worktree list` 越来越长，主会话跟进进度时要人工分辨哪些是活的。

## 要做的事

1. **新命令 `atb gc`**，默认**只预览不删除**（dry-run），逐个列出候选项和处理结论：
   - 候选：状态为 `done` 或 `dropped` 的任务，它的 worktree（`checks.resolve_worktree`）和/或分支还存在。
   - 每个候选给出结论之一：`remove`（可以清理）、`skip: dirty`（worktree 有未提交改动）、`skip: unmerged`（分支有提交没合进 target，`dropped` 任务常见）、`skip: missing`（已经不存在，无需处理）。
   - `todo`/`doing`/`review`/`rework` 的任务**一律不碰**，也不列为候选。
2. **`atb gc --apply`** 才真正执行：对结论为 `remove` 的，先 `gitops.worktree_remove`（有改动会拒绝），再 `gitops.branch_delete`（只用 `-d`，绝不 `-D`）。任何一步失败：打印原因、跳过该任务、继续下一个，最后退出码非 0。
3. **`dropped` 任务的未合并分支**：默认 `skip: unmerged`。加 `--include-unmerged` 也**不删分支**，只删干净的 worktree，并在输出里提示分支保留、需要人工确认。atb 永远不强删分支。
4. 可选参数 `gc T001 T003`：只处理列出的任务（仍然只限 `done`/`dropped`）。`--json` 输出每个候选的 `id`、`status`、`worktree`、`branch`、`action`、`reason`。
5. **只动本地**：不 fetch、不 push、不改任务单（任务单状态保持不变）；需要的 git 查询（例如"分支是否已合入 target"，可用 `git merge-base --is-ancestor`）写在 `gc.py` 里，**不要改 `gitops.py`**（T009 可能在改）。
6. **文档**：`docs/guide.md` 和 `docs/guide.zh-CN.md` 的命令表各加一行 `atb gc`，并加一小节"收尾清理"，说明 dry-run 默认、`--apply`、为什么不强删。
