【发给：OpenCode · taskboard 窗口】（做完 T040 后接着做）

## 背景

用真实数据跑 `atb export --json`，39 个任务一个会话都没对上。原因是：OpenCode 窗口用**一个长会话**连续做很多张单，会话的工作目录是 `~/代码/tokens`（或主仓库），而不是任务 worktree，所以 T036 的"按 worktree 目录对应会话"一条也匹配不到。

tokens 项目要靠这个导出算"每个任务花了多少钱"（tokens #40），所以需要把长会话**按证据切成段**，每段归到一个任务。

## 要做的事

1. **会话分段归属**（在 `sessions.py` 现有对应逻辑上扩展，不要另写一套）。对每个会话按时间顺序扫描消息/工具调用，用下面的证据确定"从这一刻起在做哪个任务"，优先级从高到低：
   1. 工具调用（读写文件、shell 命令的 cwd 或参数）里出现的任务 worktree 路径，例如 `agent-taskboard-tasks/T0xx`、`tokens-oc-*` 等，按 `.taskboard` 里各任务记录的 worktree 路径精确匹配；
   2. 消息或命令里出现的 `atb start T0xx` / `atb check T0xx` / `atb review T0xx` / `atb sync T0xx`；
   3. 兜底：落在某任务 `start` 到 `review`（没有 review 就到 done）之间的时间段，且该时间段只对应一个任务。多个任务重叠时**不要猜**，这一段不归属。
   - 同一会话相邻两段属于同一任务时合并。
   - 只读会话里的元数据（时间、cwd、工具名、命令/路径参数、token 用量），**不要**把消息正文写进输出或缓存。
2. **导出字段**：`tasks[].sessions[]` 每一项新增
   - `from`、`to`：这一段的起止时间（UTC ISO 8601）。整个会话都属于这个任务时就是会话的起止时间；
   - `basis`：`"worktree"` / `"command"` / `"time_window"`，说明这一段靠哪种证据归属；
   - `usage`：这一段的用量（`input`/`output`/`cache_read`/`cache_write`/`total`），没有数据时为 `null`。
   - 同一个会话 ID 可以出现在多个任务里（各自不同的段）。
   - 只新增字段，**schema 仍然是 1**；已有字段含义不变。任务级 `usage` 改为各段之和。
   - 更新 `docs/export.md`（中英两份）说明新字段和分段规则。
3. **测试**（fixture 用合成数据）：
   - 一个 OpenCode 长会话依次做 T001、T002、T003（分别用 worktree 路径、`atb check` 命令、时间段三种证据），导出后三个任务各得一段，`from`/`to`/`basis`/`usage` 正确，三段用量之和等于会话总量（只计入已归属的段）；
   - 两个任务时间段重叠且没有其他证据时，这一段不归属；
   - 原来"一个会话一个任务"的情况输出不变（只多了新字段）；
   - 导出里不含消息正文。
