## 背景

`atb status`、`atb board`、`atb watch` 对每个任务都要跑好几次 git 子进程（rev-list、status、diff、log…），`watch` 还每隔几十秒全部重跑。任务多了以后会明显变慢，`watch --interval 30` 甚至可能一轮还没跑完下一轮就到了。

## 要做的事

1. `scripts/bench_status.py`：在临时目录造一个有 200 个任务（其中 20 个 doing、各有 worktree 和若干提交/未提交改动）的合成仓库，测 `status`、`board --html`、`watch` 单轮扫描的耗时和 git 子进程次数。回报改动前后的数字。
2. 找出可以批量做的 git 调用（例如用一次 `git for-each-ref` 拿到全部分支 tip 和提交时间，代替每个任务各跑 `rev-parse`/`log`），以及只对活跃任务才需要的调用。
3. 目标：200 个任务时，`status` 和 `watch` 单轮扫描的 git 子进程数**至少减半**，耗时随之下降；输出与改动前**逐字一致**（加测试：同一合成仓库，新旧实现输出相同）。
4. 不改 `render.py`（T017 在改）；`cli.py` 尽量只改数据收集部分。
