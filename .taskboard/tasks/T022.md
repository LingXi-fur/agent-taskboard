## 背景

agent-taskboard 已公开（https://github.com/LingXi-fur/agent-taskboard），但 CI 只跑 ubuntu 和 macOS。tokens 项目在 Windows 上踩过这些坑：路径分隔符、`os.set_blocking` 不存在、`fstat` 和 `stat` 的 ctime 含义不同、命令行长度限制、file URI。atb 大量调用 git 和子进程，也读写 worktree 路径，很可能有类似问题。

## 要做的事

1. 在 `.github/workflows/ci.yml` 的矩阵中加入 `windows-latest`（3.11、3.12、3.13）。walkthrough 步骤在 Windows 上用 Git Bash（`shell: bash`）运行。
2. **先诊断再改。** 你可以 push 自己的任务分支来跑 CI（只能 push 本任务分支，绝不 push `main`，不要 force push 别人的分支）：`git push -u origin <本分支>`，然后执行 `gh workflow run CI --ref <本分支>`（如果 workflow 没有 `workflow_dispatch`，就顺手加上）。日志可能很大，保存到文件后只看汇总。
3. **修产品代码，不是只改测试。** 路径比较、`glob` 范围匹配（`allow`/`deny` 一律用 `/`）、worktree 路径、HOME 隔离（`--isolate-home` 在 Windows 上要设置 `USERPROFILE` 和 `APPDATA`）、`atb watch` 的终端输出、`board --html` 的文件编码（一律 UTF-8）。
4. 不要用 `skipIf(win32)` 让 CI 变绿。确实只能在某个平台上测的，在回报里逐条说明理由。
5. 所有 git 调用继续走 `gitops.git_env()`。

## 验收
- [ ] 本分支最新一次 CI 运行中，Windows、macOS、Ubuntu 全部通过（回报贴出运行链接）
- [ ] 本地 `TZ=UTC` 和 `TZ=Asia/Shanghai` 全量测试通过，`bash examples/walkthrough.sh` 退出码为 0
