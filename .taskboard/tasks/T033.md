## 背景

主会话合并 T032 时，`atb check` 和 `atb done --merge` 报了 6 个"范围越界"文件：`.taskboard/tasks/T029.md`、`CHANGELOG.md`、`docs/design/console*.md` 等。但这个分支真正改动的只有 7 个允许的文件（`git diff --stat main...分支` 可以确认），最后只能用 `--force` 合并。

原因：ZCode 开工后把 main 上的新提交快进到了自己的分支里，而 `src/agent_taskboard/checks.py` 第 26 行用的是 `gitops.changed_files(sheet.base, sheet.branch)`，也就是开工时记录的 base。main 后来新增的提交也被算成了这个分支的改动。`atb sync` 把目标分支合并进来之后，同样会出现这个问题。

## 要做的事

1. 计算"任务改了哪些文件"时，以 `merge-base(目标分支, 任务分支)` 为起点，也就是 `git diff 目标分支...任务分支` 的语义：
   - 目标分支可以解析时用 merge-base；解析不了时（例如目标分支不存在）退回到 `sheet.base`。
   - 所有用到"改动文件"的地方（status 的 FILES/VIOL 列、check、review、done 的就绪检查、board）都要走同一个函数，不要只改一处。
2. 检查 `AHEAD/BEHIND`、diffstat 是否也有同样的问题，有就一起修。
3. **测试（用真实 git 仓库）：**
   - 开工后，目标分支新增一个提交，改动范围外的文件；任务分支把它合并或快进进来，再改一个范围内的文件。`check` 不能报越界，改动文件只有那一个。
   - 任务分支自己改了范围外的文件，必须照常报越界。
   - `atb sync` 之后同样不报误报。
   - 目标分支不存在时退回到 base，不报错。
