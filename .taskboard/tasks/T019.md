## 背景

`atb review` 现在只输出 Markdown（T017 刚加了"活动与历史"段）。协调者和脚本想程序化地判断"能不能合"，只能解析 Markdown。`status`、`board`、`doctor`、`log`、`gc`、`watch` 都已经有 `--json`，只有 `review` 没有。

## 要做的事

1. `atb review ID --json`：输出一个 JSON 对象，字段与 Markdown 审查单一一对应：id、title、agent、status、branch、base，scope（denied/outside/uncommitted 三个列表），test（最近结果 + 详情），activity（dirty、idle_seconds、rework_count、status_history），doctor_fails，diffstat（结构化为 files 列表 + 合计，不是原始文本），conflicts / mergeable / drift，acceptance（清单条目和是否勾选）。
2. 加一个顶层 `ready` 布尔值和 `blockers` 列表：没有越界、没有未提交改动、最近测试通过、可合并、没有 doctor FAIL 时 `ready=true`；否则把每条原因写进 `blockers`（稳定的英文 code + 人类可读的说明，例如 `{"code": "uncommitted", "message": "..."}`）。
3. `--json` 与 `--out FILE` 可以一起用；与 `--lang` 一起用时 JSON 的 key 不变，只有 `message` 跟随语言。
4. `review --json` 和 Markdown 版一样，会把 `doing` 改成 `review`（行为保持一致，文档写清楚）。
5. JSON 必须用 `json.dumps(..., ensure_ascii=False, sort_keys=True)` 输出，便于对比。
