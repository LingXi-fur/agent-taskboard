## 背景

T019 的 `review --json` 和 T023 的 READY 列已经能算出 `ready` 和 `blockers`，但 `atb done --merge` 合并前并不看这些结果。协调者可能把测试没过、有未提交改动或越界的任务直接合进去。

## 要做的事

1. `atb done ID --merge` 合并前调用和 `review --json` 同一个 `evaluate_readiness`，判断依据也必须完全相同，不要另写一套。
   - 有 blocker 时拒绝合并：逐条列出 blocker 代码和说明，以非零码退出，什么都不改。
   - `--force` 可以跳过检查，但要打印"已忽略的 blocker"清单。原有的 `--force` 语义（允许完成 doing 任务）保持不变，帮助文本写清楚它现在同时覆盖这两件事。
   - 配置项 `require_ready_for_done`，默认 `true`。设为 `false` 时恢复旧行为，只打印警告、不拒绝。
2. `test_not_passed`：如果任务单的 `test` 字段为空、也从没跑过测试，说明这个仓库可能根本没配测试命令。此时拒绝信息里要提示怎么配（`atb check ID --test` 或者在任务单里填 `test`）。
3. 不要改变 `--push`、`--clean` 的顺序和语义。
