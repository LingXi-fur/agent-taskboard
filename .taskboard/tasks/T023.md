## 背景

T019 新增了 `atb review --json`，输出 `ready` 和 `blockers`；T021 新增了 `atb done --merge --push` 和"未推送提交数"。现在协调者要逐个运行 `atb review` 才知道哪些任务可以合并，而且文档还没写这两个新功能（T020 是在它们合并之前写的）。

## 要做的事

1. **`atb status` 和 `atb board --html` 显示每个任务能否合并。**
   - 对状态为 `review` 的任务（`doing` 状态但已有提交的也可以显示），新增一列 `READY`：✓，或者 ✗ 加上第一个 blocker 的代码（如 `✗ test_not_passed`）。
   - HTML 中悬停显示完整的 blockers 列表，中英文跟随 `--lang`。
   - 直接复用 `render.build_review_json` 中的 `ready`/`blockers` 逻辑，**不要另写一套判断**；需要的话把判断提成一个公共函数。
   - 注意性能：T018 把 200 个任务的 `status` 优化到了约 0.35 秒，不能明显退化。合并冲突检查（merge-tree）只对 `review` 状态的任务做；用 `scripts/bench_status.py` 前后各测一次，把数字写进回报。
2. **`status --json` 给每一行加上 `ready` 和 `blockers` 字段**，顶层结构不变。
3. **文档：** 在 `docs/guide.md`、`docs/guide.zh-CN.md` 和两份 README 中补上：
   - `atb review --json`：字段说明、blocker 代码表，以及一个用 `jq` 筛出可合并任务的例子。
   - `atb done --merge --push`、`push_after_done` 配置和 `--no-push`。
   - 新的 `READY` 列。
   - 中英文内容保持一致。
