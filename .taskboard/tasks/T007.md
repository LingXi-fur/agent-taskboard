## 背景

1. **返工后进不了审查**：T006 被 `atb rework` 打回，OpenCode 在原分支追加提交后，状态仍然是 `rework`。`atb review` 只会把 `doing` 改成 `review`，`atb done` 只接受 `review`，结果主会话只能先手动 `atb start T006`（rework → doing），再 `review`，再 `done`。`rework` 的交接文本里也没有说改完之后要做什么。
2. **转发清单全靠手写**：主会话同时指挥 4 个窗口、2 个项目，每一轮都要手写一张"哪个工具 · 哪个窗口 · 发哪句话"的表（tokens 仓库里的 `转发清单.md`）。用户明确要求：先按**项目**分，再写工具 · 窗口，最后才是文件。
3. **测试污染用户环境**：tokens 项目有个测试没隔离缓存，每跑一次全量测试就把用户真实的 `~/Library/Caches/...` 缓存覆盖掉，Agent 回报的"测试全过"完全看不出来。主会话是用 `HOME=$(mktemp -d)` 跑测试才发现的。

## 要做的事

1. **返工流程**
   - `atb review` 同时接受 `doing` 和 `rework`，把状态改成 `review`（`todo`、`done`、`dropped` 仍然报友好错误，退出码 2）。
   - `atb prompt` 在任务状态为 `rework` 时，"返工"小节的末尾加一句固定提示：在原分支追加提交，完成后运行 `atb check <ID> --test` 并回报（中英文两套）。
   - `atb done` 的报错信息里，如果状态是 `rework` 或 `doing`，提示下一步该运行哪条命令。
2. **新命令 `atb dispatch`**：生成转发清单（Markdown，输出到 stdout，`--json` 可选）。
   - 只列 `todo`、`doing`、`rework` 状态的任务；每行写：任务 ID、标题、agent、状态，以及"发这句话"。这句话是一行中文，例如：`请在 /abs/path 运行 PYTHONPATH=src python3 -m agent_taskboard prompt T007，按交接文本执行。全程中文，完成后不要 push、不要合并。` 返工的任务用"T007 被打回了……最前面的'返工'小节就是要改的内容"这种说法。
   - 最上面一行是项目名（仓库目录名），用 `## 项目：<name>` 作标题，方便主会话把多个仓库的输出直接拼在一起。
   - 任务单的 front matter 新增**可选**字段 `window = "..."`（例如 `"OpenCode · taskboard 窗口"`）。有 `window` 就按 window 分组显示，没有就按 agent 分组。旧任务单没有这个字段，必须照常解析。
   - `--lang en` 输出英文版本。
3. **测试时隔离 HOME**
   - `atb check --test` 新增选项 `--isolate-home`：在临时目录里新建 HOME（同时设置 `XDG_CACHE_HOME`、`XDG_DATA_HOME`、`XDG_CONFIG_HOME` 指向它下面的子目录），在 worktree 里跑测试命令，跑完列出临时 HOME 下新出现的文件（相对路径，最多 20 个，超出写"另有 N 个"）。
   - 有新文件时，`check` 的结果标为 `home_writes`，退出码为 1，并在输出里写"测试写入了 HOME"；没有就和现在一样。
   - `.taskboard/config.toml` 支持 `isolate_home = true` 作为默认值，命令行参数优先。
   - 注意：临时 HOME 下没有 git 全局配置，测试命令如果需要 git 身份，要用环境变量 `GIT_AUTHOR_NAME` 等补上，不能读用户的 `~/.gitconfig`。
