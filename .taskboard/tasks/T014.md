## 背景

审查一个任务时，主会话想知道：它什么时候开工、被打回过几次、每次测试结果如何、什么时候合并的。现在这些信息散在任务单的 git 历史和 `.taskboard/runs/<ID>.jsonl` 里，只能手动翻。

## 要做的事

新命令 `atb log ID [--json] [--verbose]`，按时间顺序列出这个任务的事件：

1. **状态变化**：遍历 `git log --follow -- .taskboard/tasks/<ID>.md` 的每个版本，解析出 `status`，相邻不同就记一条 `todo → doing`，附提交时间和短哈希。解析失败的历史版本跳过并计数，不中断。
2. **测试运行**：读 `.taskboard/runs/<ID>.jsonl`，每条一行：时间、退出码、耗时。**默认不显示测试输出**；`--verbose` 时只显示输出的最后 5 行。
3. **合并**：在 `target` 分支上找合并了该任务分支的提交（例如提交信息含任务分支名，或 `git log --merges` 的第二父提交是该分支 tip），记一条"已合并"。分支已删除时也要尽量找到（按提交信息）。
4. **返工记录**：任务单正文里的返工小节（`atb rework` 追加的）列出条数和每条的第一行。
5. 输出示例：`2026-11-16 18:05  a1b2c3d  todo → doing`、`2026-11-16 18:40  测试 exit 0（24.5s）`、`2026-11-17 04:30  已合并（75e57f0）`。时间按本地时区。
6. 只读。逻辑放 `history.py`。
