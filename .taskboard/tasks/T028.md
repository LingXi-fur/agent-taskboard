## 背景

任务分支经常是从旧的目标分支拉出来的，最近几轮 tokens 的 #23 和 #24 都遇到过：合并时冲突，或者 CI 在已经修好的旧问题上失败。现在只能让 agent 自己手动 rebase。`atb status` 的 AHEAD/BEHIND 列能看到落后多少，但没有一键同步的办法。

## 要做的事

1. 新命令 `atb sync ID [--rebase | --merge] [--dry-run]`：把目标分支的最新提交同步进任务分支，在任务的 worktree 里执行。
   - 默认用 `--rebase`。worktree 有未提交改动时拒绝执行，并提示先提交或暂存。
   - 有冲突时自动 `--abort`，恢复原状，列出冲突文件，以非零码退出。不要把 worktree 留在半 rebase 的状态。
   - `--dry-run`：用 `git merge-tree` 预测会不会冲突，以及会冲突的文件，不做任何改动。
   - 如果任务分支已经 push 到远端，rebase 后需要 force push。atb **不负责 push**，只在输出里提醒："分支已在远端，rebase 后需要由 agent 执行 force-with-lease"。
2. `atb status` 里 BEHIND 大于 0 的任务，在提示行显示 `atb sync ID` 的建议，只显示前 3 个。
3. `atb prompt ID` 生成的交接文本中，如果任务分支落后目标分支，加一句"开工前先运行 atb sync ID"。
4. 所有 git 调用都走 `gitops.git_env()`。
