## 背景

atb 0.1.0 已经完成，README 讲清楚了每条命令，但还缺一份"一个主会话指挥多个 Agent 窗口"的完整使用指南。这正是 atb 诞生的场景：主会话同时管 tokens 和 agent-taskboard 两个仓库、4 个 Agent 窗口（OpenCode × 2、Gemini × 2）。现有 CI（`.github/workflows/ci.yml`）只跑默认时区，也没有检查打包。

## 要做的事

1. **`docs/guide.zh-CN.md` 和 `docs/guide.md`（中英两份，内容对应）**：多 Agent 协作指南。
   - 角色：主会话（写任务单、审查、合并）和 Agent 窗口（按交接文本干活，不 push、不合并）。
   - 一个任务的完整生命周期，每一步配命令：`new` → `start` → `prompt`（转发给 Agent）→ Agent 干活 → `check --test` → `review` → 不合格 `rework` / 合格 `done --merge --clean`。用一张 Mermaid 状态图画出 todo / doing / review / rework / done / dropped 之间的转换（以当前 main 上 `cli.py` 的实际规则为准，不要照 T007 计划中的行为写）。
   - 并行任务：怎么用 allow / deny 把两个 Agent 隔开，怎么用 `conflicts` 提前发现撞文件，怎么用 `status` 看基线漂移。
   - "真实踩过的坑"一节：从 `DESIGN.md` 第 1 节和 `.taskboard/tasks/T001–T006.md` 的返工记录里挑 3–5 个真实案例（例如 T003 的 merge-tree 误判、T006 的离线打包），每个写清楚现象、原因、atb 是怎么防住的。
   - 只引用仓库里真实存在的命令和参数，写完逐条对照 `atb <cmd> -h` 核对一遍。
2. **CI 补强（`.github/workflows/ci.yml`）**：
   - 单元测试在 `TZ=UTC` 和 `TZ=Asia/Shanghai` 下各跑一遍（用 matrix 或分两个步骤都可以）。
   - 新增打包检查：`pip install "setuptools>=70.1" build`，然后 `python -m build`，再在新的 venv 里 `pip install dist/*.whl`，最后运行 `atb --version`，断言输出里有 `pyproject.toml` 中的版本号。
