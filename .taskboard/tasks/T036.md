## 背景

`atb sessions` 已经能把 agent 会话对应到任务，但每个任务"花了多少 token"现在还看不到。目前只有 codex 的 adapter 会填 `Session.usage`。T036 先补齐 token 用量，再按任务汇总。

**只统计 token 数，不换算成金额。** atb 是通用工具，价格表不归它管。

## 要做的事

1. **补齐各 adapter 的 `usage`。** 统一用这几个键：`input`、`output`、`cache_read`、`cache_write`、`total`。拿不到的键就不写，不要填 0。
   - **claude_code：** 累加 assistant 消息里的 `message.usage`。同一条消息在流式输出时会写好几行，要按 `message.id`（再加上 `requestId`）去重，否则会重复计数。
   - **gemini_cli、opencode：** 读它们会话文件里已有的 token 字段。
   - 某个工具确实没有记录 token，就保持 `None`，并在 adapter 的文档字符串里写明原因。
   - 每个 adapter 都要用造出来的小样例做测试，包括去重。
2. **按任务汇总。** 新增一个函数：把对应到同一个任务的会话的 `usage` 加起来，并记下有几个会话、其中几个没有用量数据。这里复用 `atb sessions` 现有的会话→任务对应关系，不要另写一套。
3. **在哪里显示：**
   - **`atb review ID`：** 文本输出和 `--json` 都加一节"token 用量"，写明：会话数、各项 token、没有用量数据的会话数。
   - **`atb stats`：** 每个 agent 增加"平均每个已完成任务的 token 数"。没有数据时显示"—"。
   - **控制台：** 任务详情里显示同样的信息；`/api/v1/tasks/ID` 返回 `usage` 字段，并在 `docs/api.md` 里写明。
4. **性能：** 读会话文件要有上限。沿用 adapter 现有的头部和尾部读取窗口；大文件只做流式累加，不要整个读进内存。`atb review` 的总耗时增加不能超过 1 秒，回报里写出你实测的数字。
